## 最新一轮实测（00:48–00:51，`evidence/` 里存的就是这一轮）

链路比 00:18 那次跑得更远，15 步全过到 ANAL：
```
start 200 → start2 200 → clear 200 → nodes 200 (30) → sect 200
→ matl 200 (E=6000000000Pa) → elems 201 (46) → elems_chk 200 (ELEM 已挂 MATL)
→ matl_chk 200 "GET 未回显 ELAST（共享会话传播延迟，PUT 已过，交 ANAL 终验）"
→ cons 201 → stld 201 → comb 201 → bodf 201 → bmld 201
→ analyze 200 (9.0s)  {"error":{"message":"[错误] 材料 没有定义。"}}
→ 降级 red_source=表格3快照, degraded=true, moment=null
```
两点判断：
1. **MIDAS 云侧完全接受建模写入与荷载**（14 步 200/201），**唯一失败点是材质**，且由 `analyze` 给出确定错误 → 这是**我方材质载荷问题**，不是"云侧不认竹材/不认 USER 材质"。
2. 门禁从"GET 回读即失败"改成"交 ANAL 终验"——**方向是对的**（ANAL 才是材质的真实消费者，也确实在 9 秒内给出了确定错误）。代价是 `matl_chk` 那一步不再拦，所以**必须保证 ANAL 错误一定走降级**（这轮走了，`degraded=true / moment=null`，没伪造）。

⚠️ **待辨的两个候选变量现在混在同一个请求里**（`duel_run.py:271-274`）：① `ELAST=6e9`（kPa 单位制下 = 6000 GPa，超范围）；② 材质 `NAME` 含 `( ) , ` 与空格（`bamboo(E=6GPa,M2open)`）——历史成功那条叫 `Q355`（纯字母数字）。
**做对照实验才能确认真因**：发两次 PUT，一次只改单位（`ELAST=6000000`、名字保持带括号），一次只改名字（`NAME=BAMBOO`、`ELAST` 保持 6e9），各自看 ANAL 是否不再报"材料没有定义"。这个结论要写进 `MIDAS_API_接入手册.md`，是真正的沉淀。
